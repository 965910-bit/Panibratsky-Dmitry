## Портфолио и AI-ассистент

Главная страница — статическая (`index.html`, `css/executive.css`, `js/executive.js`). Существующие разделы и URL сохранены. Публичное резюме для скачивания не создавалось без отдельного согласия: кнопка предлагает запросить его по почте. Ранее опубликованные документы с прежней фамилией и сканы сертификатов исключены из текущей версии сайта; оригиналы локально перемещены в игнорируемую папку `resume/private-archive/`, недоступную через сервер превью. Файлы архива не входят в Git и не будут автоматически перенесены при клонировании: сохраните нужные оригиналы в личном хранилище. До публикации изменений прежние документы остаются на действующем сайте; после публикации проверьте прямые URL. Копии в истории Git, старых развёртываниях или кэшах могут оставаться доступными и требуют отдельной проверки.

### Локальный запуск

Нужен Node.js 20 или новее. Установка npm-пакетов для сайта и ассистента не требуется:

```sh
npm start
```

Откройте `http://localhost:3000`. Без `OPENAI_API_KEY` сайт работает, но AI-ассистент честно сообщает, что временно недоступен. Для локальной настройки передайте ключ через переменную окружения на сервере, **не добавляя его в репозиторий**. Можно указать `OPENAI_MODEL`; значение по умолчанию — `gpt-4o-mini`. Запросы идут на `https://api.openai.com/v1/chat/completions`; необходимы действующий ключ, доступ к модели и настроенный биллинг провайдера. Не размещайте ключи в браузере, HTML, JavaScript или логах.

### Публикация ассистента

GitHub Pages отдаёт только статические файлы и не запускает Node.js: одной публикации репозитория недостаточно для работы AI. Для продакшена разверните `server/assistant.js` в отдельном Node-хостинге, установите `OPENAI_API_KEY` как секрет на сервере и настройте HTTPS reverse proxy на том же домене сайта: `GET /api/chat` и `POST /api/chat` → backend. GET показывает только наличие конфигурации ключа, без обращения к модели; это не проверка провайдера, биллинга или гарантии ответа. Прокси должен сохранять исходный `Host` для проверки Origin. Браузер обращается только к относительному `/api/chat`; никаких localhost-адресов в браузерном коде нет. При отсутствии сервиса сайт остаётся доступным, а окно чата показывает сообщение об ошибке и ссылку на контакт.

До включения в продакшене необходимо выбрать и согласовать провайдера и регион обработки данных, политику конфиденциальности и затраты; проверить лимиты и биллинг, задать квоты на стороне провайдера и настроить защиту от автоматических запросов на уровне прокси. Встроенные лимиты — только базовая защита в памяти одного процесса: при перезапуске и нескольких экземплярах счётчики не общие, а за прокси посетители могут разделять один IP. Они не заменяют распределённый rate limiting, WAF, бюджетные ограничения и мониторинг. Сообщения отправляются внешнему AI-провайдеру, поэтому пользователь предупреждается не вводить персональные или конфиденциальные данные; сервер не сохраняет историю чата. Полностью предотвратить ошибки модели и prompt injection нельзя — важные ответы следует проверять.

База фактов для ассистента находится в `server/assistant.js` и составлена по предоставленному резюме. Ссылки под ответом ведут к материалам портфолио и не являются автоматической проверкой каждого утверждения. Обновляйте базу при изменении данных и не добавляйте неопубликованные личные сведения. Если понадобится независимый хостинг API, подключайте его через собственный прокси; секреты и конечные точки провайдера не должны передаваться клиенту.

На новой главной подключены подтверждённый пользователем поток Google Analytics `G-DM41FJYWX0` и счётчик Яндекс Метрики `108401876` без Вебвизора. Прочие страницы могут сохранять прежние счётчики, настройки отдельных страниц и кабинета требуется проверять отдельно. В локальной версии страницы новостей Вебвизор отключён и поисковый запрос не передаётся как параметр события. Перед публикацией проверьте применимые требования к уведомлению и согласию на cookies и политике обработки данных; управление согласием здесь не реализовано. В настройках расширенной статистики GA4 проверьте сбор взаимодействий с формами и параметры событий, чтобы в аналитику не попадали вопросы AI-чату и другие персональные данные. Не добавляйте содержимое чата или контактные данные в события аналитики. После публикации проверьте посещение главной в отчёте Realtime/DebugView: наличие тега в коде само по себе не подтверждает приём данных.

### Автоматизация и ограничения данных

HH workflow намеренно завершается ошибкой при сбое или пустом сборе и не заменяет предыдущие данные, если одна из двух выборок не собрана. Зарплатные показатели учитывают только значения `from` в рублях, это не средняя зарплата рынка. Доступность HH, полноту выборки и причину прежнего сбоя push необходимо проверить после запуска в Actions. Страница `analytics.html` показывает только данные нового формата с метаданными источника; прежние демонстрационные файлы и кабинет отображают сообщение о недоступности до успешного сбора и публикации. Показано время сбора и предупреждение при возрасте более 72 часов. Калькулятор найма — сценарий по скорости, введённой пользователем, а не прогноз рынка. Реальные ответы HH и их полнота не проверялись. Для диагностики workflow, запущенный на ветке, отличной от `main`, не перезаписывает файлы и не делает push; ошибки выводятся в аннотацию Actions только категорией и, при наличии, HTTP-кодом и номером страницы. Статус `403` или `429` нельзя обходить: нужно соблюдать правила и ограничения источника. Изолированный ручной запуск Actions `44087906290` получил HTTP 403 на первой странице и не публиковал данные. Причина отказа по одному коду неизвестна; необходимы проверка официальных условий доступа и, при необходимости, обращение к поддержке hh. Этот результат не доказывает причину предыдущих ошибок.

Для разовой проверки официального API добавлен `python scripts/hh_auth_probe.py --confirm-read-only`: он скрыто запросит **уже выданный токен приложения** (не Client Secret), выполнит один GET `/vacancies` и покажет только результат, HTTP-код и известную категорию ошибки. Токен также можно передать через `HH_APP_ACCESS_TOKEN` в окружении защищённой сессии; не передавайте его аргументом команды и не сохраняйте в файлах репозитория. Получение токена описано в [документации hh](https://github.com/hhru/api/blob/master/docs/authorization_for_application.md): не запрашивайте новый без необходимости, поскольку прежний токен приложения отзывается. Проба не получает и не обновляет токены, не следует перенаправлениям, не сохраняет вакансии и не публикует данные. `ok` подтверждает только полученный корректный ответ на один запрос, но не полную выборку, стабильность или право на регулярный сбор. Проверяйте права и условия hh; при отказе не обходите ограничения. Скрипт не подключён к Actions и не меняет существующий сбор; реальный запуск с авторизацией пока не выполнен.


Telegram сообщает об ошибке неполной доставки и сохраняет успешные отправки. Cache Actions не является надёжным долговременным журналом. При отсутствии журнала отправка останавливается; при устаревшем кэше или сбое между доставкой и сохранением дубликаты всё ещё возможны. Фактическая доставка, состояние секретов и работу внешних сервисов нужно проверить отдельно. Внутренние отчёты исключены из Pages, но доступны в публичной истории Git; исключение не отменяет необходимости смены ранее раскрытых паролей и проверки сессий.

Node-зависимости Telegram зафиксированы в `package-lock.json`, workflow устанавливает их через `npm ci --ignore-scripts`. Для проверки используйте `npm test` и `npm audit --omit=dev`; audit отражает состояние базы npm на момент запуска, а не гарантирует отсутствие любых рисков.

Данные в конструкторах аудита/чек-листов, отдельных отчётах и планировщике экранируются при отображении. Это не означает, что вся платформа проверена на все способы внедрения кода; не используйте её для конфиденциальных данных до отдельной проверки и настройки защищённого хранилища.

### Офлайн-режим

Service worker сохраняет только автономную страницу `offline.html`, а не новости, формы или содержимое кабинетов. При потере сети на выбранных публичных страницах показывается сообщение с предложением восстановить связь и позвонить. Он устанавливается со страницы новостей; до первой успешной установки офлайн-страница недоступна. При изменениях страницы или логики нужно обновлять версию кэша.

### Надёжность новостей

Сборщик различает пустой ответ доступного источника и ошибку. Если все основные источники недоступны, задача завершается ошибкой, а прежний `data/news.json` сохраняется; при частичном сбое выдаётся предупреждение. Пустая выдача сама по себе не подтверждает полноту данных. У новых записей без подтверждённой даты публикации дата остаётся пустой; дата письма Google Alerts не подменяет дату статьи. Время сбора сохраняется отдельно для срока хранения недатированных материалов и не отображается как дата публикации. Ранее собранные записи могут содержать время получения вместо даты публикации — проверяйте источник. `data/news.json` вручную не изменялся.

### Переход к новости из Telegram

Новые сообщения бота ведут на соответствующую запись текущей ленты через фрагмент ссылки; исходная статья остаётся доступна отдельной кнопкой. Если запись больше не хранится в ленте или JavaScript недоступен, воспользуйтесь ссылкой на источник в сообщении. Очень длинные адреса вместо этого ведут к общей ленте. Старые сообщения не меняются. Фрагмент адреса может быть доступен браузерным скриптам и средствам аналитики, поэтому он предназначен только для публичных новостных URL.

### Тематический фильтр Telegram

Перед публикацией бот ищет операционные термины в заголовке и описании (склад, поставки, грузоперевозки, запасы, WMS и др.). Темы оповещений Google, теги и рубрика источника отдельно не считаются доказательством релевантности; техническая тема Google Alerts помечается как тема, а не заголовок статьи. Неподходящие записи остаются в исходной ленте и не отмечаются отправленными. Фильтр эвристический: он может пропустить полезное или допустить неуместное, не проверяет достоверность, не заменяет редактора и применяется только к новым отправкам. При отсутствии совпадений бот ничего не публикует. Реальную отправку необходимо проверять отдельно.

### Предпросмотр Telegram без отправки

Выполните `npm ci --ignore-scripts`, затем `node scripts/telegram-news.js --preview`: команда использует тот же отбор и формат, что реальная отправка, показывает до пяти кандидатов в журнале, не требует токена и не сохраняет состояние отправок. Если `data/sent_news.json` отсутствует, она предупреждает: возможно, часть выбранных материалов уже отправлялась. Испорченный журнал приводит к ошибке. Предпросмотр не является подтверждением публикации и не блокирует обычное расписание.

После публикации workflow **Preview Telegram Digest** в основной ветке его можно запустить вручную в GitHub Actions, выбрав нужную ветку, и посмотреть журнал шага Preview without sending. Он только пытается восстановить доступный кэш отправок и не сохраняет его; из-за ограничений области действия или очистки кэша состояние может отсутствовать или отличаться от используемого следующим запуском. Между предпросмотром и отправкой лента и журнал могут измениться. Сами сообщения workflow не публикует и секреты Telegram ему не нужны.

### Безопасное восстановление журнала Telegram

Исторический `data/sent_news.json` находится в репозитории и может устареть: оба workflow удаляют его только во временной копии runner перед восстановлением кэша. Если журнал не восстановлен, обычная рассылка завершится ошибкой без отправки, даже при пустой ленте. При локальном запуске файл из checkout не считается доказательством актуальности журнала. Сначала попробуйте восстановить актуальный `data/sent_news.json` из надёжной резервной копии: это JSON-массив полных ссылок. Кэш GitHub Actions не является такой гарантированной копией. Не создавайте пустой файл для уже действующего канала: это может привести к повторным публикациям.

Если точной копии нет, предусмотрена **осознанная инициализация с пропуском всей текущей ленты**. После публикации этого workflow в основную ветку вручную запустите `Send Telegram Digest` на нужной ветке с режимом `initialize`. Команда `node scripts/telegram-news.js --initialize-journal` записывает все допустимые ссылки текущего `data/news.json` как уже обработанные, без отправки и без токена. Она не перезаписывает существующий журнал и не работает с пустой лентой. Это означает, что все текущие материалы, включая ещё не опубликованные, будут пропущены; материалы, появившиеся позднее, смогут попасть в последующие рассылки. На следующих запусках режим будет обычным; сохранение/доступность кэша нужно проверить в журнале Actions. У кэша есть ограничения видимости между ветками, поэтому выбирайте ту же ветку, что использует расписание.

Это не долговременная база и не гарантия однократной доставки: устаревший кэш, ошибка его сохранения, либо сбой после принятия сообщения Telegram и до записи состояния могут привести к дубликатам. Предпросмотр и инициализация не блокируют обычное расписание в будущем.

### Локальный визуальный предпросмотр новостей

`node tools/telegram-draft-preview.js > draft-preview.html` создаёт локальную HTML-страницу с примерами карточек и текста из `data/news.json`. Откройте файл в браузере. Скрипт не обращается к сети, не меняет данные и не отправляет сообщения; ссылка на первоисточник открывается только по действию читателя. Предпросмотр не является Telegram-очередью, не использует журнал отправок и может показать уже опубликованные новости. Описание берётся из ленты без фактчекинга, комментарий оставлен пустым. HTML-карточка — макет, а не готовый PNG для Telegram. Файл предпросмотра исключён из Git и не должен публиковаться. Для тестов: `node --test tests/telegram-draft-preview.test.js`.

Автоматический workflow отправки отключён на уровне GitHub Actions. Не включайте его до готовности проверенной очереди и отдельного согласования. Локальный макет не реализует Telegram-бота, кнопки одобрения или устойчивое хранилище.

### Основа ручного согласования Telegram

В `telegram-review/` находится неразвёрнутый прототип Cloudflare Worker/D1 для отправки подготовленных текстов редактору и публикации только после подтверждения. Он ещё не подключён к сборщику или основному каналу; отправка изображений проверена только в имитационных тестах. Условия безопасности, неопределённой доставки и оставшиеся этапы описаны в `telegram-review/README.md`. Автоматический workflow отправки остаётся отключённым; не включайте его ради этого прототипа.

### Визуальные карточки для черновиков

Локальный генератор PNG и инструкция находятся в `telegram-review/card.py` и `telegram-review/README.md`. Прототип поддерживает передачу карточки на согласование, но не развёрнут и не проверен с реальным Telegram; источник и внешний вид нужно проверить вручную.

Автосбор RSS «Логистика 360» приостановлен в коде до выяснения разрешения: [правила источника](https://logistics360.ru/copyright-rules/) запрещают автоматизированное извлечение без официального разрешения. Доступность RSS сама по себе его не подтверждает. Исторические записи и ранее опубликованные материалы не удалены; они требуют отдельной проверки прав. Другие источники также требуют проверки условий. Автосбор ATI.SU также приостановлен по решению владельца на время выяснения условий; при этом применение ограничений соглашения ATI к новостному подразделу необходимо уточнить. В программе нет активных основных источников: основной сбор и импорт Google Alerts в ленту пропускаются с предупреждением, существующий `data/news.json` сохраняется и не становится свежим. Настроенный сбор Google Alerts отдельно может продолжаться, но данные в ленту пока не импортируются. Исторические ссылки и ранее опубликованные данные не удалены автоматически. Workflow Update News и Prepare Telegram gallery снова включены после слияния ограничений; ручной запуск галереи прошёл, но её облачное содержимое отдельно не проверено. Новый запланированный запуск обновления новостей с этими ограничениями требует проверки.

График на странице новостей использует локальную сборку Chart.js 4.5.1 (MIT), а не внешний CDN. Сборка и лицензия сверяются в CI с точной версией из `package-lock.json`; при обновлении библиотеки необходимо обновить и локальный файл, его имя в HTML и проверку CI. Dependabot предлагает обновления npm и GitHub Actions; `npm audit --audit-level=high` проверяет зависимости в CI. Это не проверка всех внешних ресурсов или гарантия отсутствия уязвимостей.

Проверка доступности исторических новостей временно отключена в GitHub как `Check Broken Links`: прежний запуск обращался к ссылкам из сохранённой ленты, в том числе к источникам, автоматический сбор которых приостановлен. Обновлённый `scripts/check_broken_links.py` допускает только точные HTTPS-хосты из явного списка `APPROVED_HOSTS`; список пока пуст. Переходы по перенаправлениям не выполняются, ответы 3xx и ошибки доступа считаются неопределёнными, а не основанием отметить страницу недоступной. При пустом списке запросов и изменений нет, выводится предупреждение: ссылки не проверены. После слияния этой защиты workflow можно отдельно вернуть в работу, но он ничего не проверит, пока доступ к конкретным хостам и допустимая частота не согласованы и не настроены. Остальные способы доступа и права на старые материалы требуют отдельного рассмотрения.

RSS: повторная генерация без изменений содержимого сохраняет прежний файл и `lastBuildDate`, чтобы запуск расписания не выдавался за обновление материалов. При изменении содержимого дата отражает время сборки RSS, а не обязательно дату публикации или сбора каждой новости; ранее записанные даты задним числом не исправляются. Отсутствие разрешённых источников означает, что новости могут быть неактуальны.
