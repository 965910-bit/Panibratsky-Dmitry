# Аудит портфолио scm-news.ru

Дата: 16 ноября 2026 года. Объект: состояние репозитория на коммите `bc22ded`.

Этот отчёт фиксирует исходное состояние до исправлений; результаты работы после аудита описаны в `ИСПРАВЛЕНИЯ-АУДИТА.md`.

## Границы проверки

Проведён статический анализ HTML, JavaScript, robots.txt, sitemap, RSS, настроек PWA и скриптов публикации; локально проверены XML и наличие файлов по ссылкам. Проверка опубликованного сайта, HTTP-заголовков, фактической индексации и позиций, браузерное тестирование, Lighthouse/Core Web Vitals, проверка облачных правил и стороннего backend не проводились. Результаты относятся к коду в репозитории; опубликованная версия может отличаться. Это не исчерпывающий пентест и не юридическое заключение.

## Критические проблемы

### 1. Пароль опубликован в форме входа — P0

**Доказательство:** `login.html:56–57`: в HTML заранее заполнены email и пароль; `login.html:76–80` передаёт их в Firebase Authentication. Действительность пароля не проверялась. Сам Firebase web API key в конфигурации не следует считать секретом автоматически; решающее значение имеют правила доступа и настройки проекта.

**Риск:** если пароль действует или использовался повторно, учётная запись и связанные ресурсы могут быть скомпрометированы. Удаление значения из файла или истории само по себе не отзывает пароль.

**Действия немедленно:** сменить пароль в Firebase и везде, где он повторялся; отозвать активные сессии и проверить пользователей, журналы входов и правила Firebase/Storage/Firestore. Убрать автозаполнение из опубликованного HTML и истории в рамках процедуры реагирования, учитывая, что история могла быть скопирована. Включить MFA, если доступно для соответствующего типа учётной записи.

### 2. «Защита» кабинетов выполняется только в браузере — P0

**Доказательство:** `cabinet.html:435`, `cabinet.html:1164–1177` и аналогичный код `promotion.html`: пароль виден в исходнике и на странице, а авторизация зависит от значения в `localStorage`. `admin.html` загружается без проверки Firebase; успешный вход в `login.html` лишь перенаправляет на него. `robots.txt` не является контролем доступа.

**Риск:** любой посетитель, получивший статический файл, может обойти интерфейсную блокировку. При этом данные в localStorage принадлежат текущему браузеру, а не автоматически раскрывают данные других посетителей. Фактический доступ к серверным данным зависит от правил backend и пока не установлен.

**Действия:** не размещать приватные данные и административные функции на публичном статическом хостинге; перенести защищённые данные за серверную авторизацию и проверку прав на каждом запросе. Проверить настройки Google Apps Script, используемого `cabinet.html:436, 520, 626`: сервер должен самостоятельно проверять идентичность и права, включая операции чтения подписчиков и заявок. Не обращаться к реальным данным до согласования и безопасной проверки.

## Индексация и SEO

### 3. Sitemap не является корректным XML — P1

`sitemap.xml:304` содержит неэкранированный `&` в URL; стандартный XML-парсер завершился ошибкой на строке 304. `scripts/generate_sitemap.py` вставляет ссылки напрямую, поэтому ошибка повторится при автоматическом обновлении. Из 106 `<loc>` только 6 относятся к scm-news.ru, остальные 100 ведут на сторонние сайты. Собственные страницы, например `career.html`, `projects.html`, `calculators.html` и `wiki.html`, отсутствуют. Главная указана как `/index.html`, тогда как её canonical — `/`.

**Действия:** исправить именно генератор и перегенерировать файл: использовать XML-библиотеку, включить только выбранные для индексации собственные канонические URL, главную указать как `/`, выставлять `lastmod` только при реальном изменении. Добавить автоматическую XML-валидацию и проверку доменов в CI. Учитывать намеренно закрытые через `noindex` страницы.

### 4. Внутренние страницы указывают canonical главной — P1

`about.html`, `blog.html`, `career.html`, `contact.html`, `experience.html`, `expertise.html`, `prompts.html` содержат canonical `https://scm-news.ru/`. Для самостоятельных страниц это сигнал объединять их с главной и может мешать их отдельной индексации; окончательное решение принимает поисковая система. У ряда других публичных страниц canonical отсутствует.

**Действия:** определить индексируемые страницы, назначить каждой корректный абсолютный self-canonical, согласовать ссылки, sitemap и редиректы. Проверить результат через инспекцию URL в Google Search Console и Яндекс Вебмастере.

### 5. Robots блокирует ресурсы для рендеринга — P1

`robots.txt:4–5, 14–15` запрещает `/js/` и `/data/`. Новости в `trends.html:879, 956–965, 1335` подгружаются JavaScript из `data/news.json`; блокировка мешает поисковому роботу получить ресурсы для отображения. Запрет сканирования не гарантирует удаления URL из индекса и не защищает данные.

**Действия:** разрешить ресурсы, необходимые для публичного рендеринга; для действительно приватного — серверная защита, а для неиндексируемого публичного — доступный роботу `noindex` или соответствующий HTTP-заголовок. Проверить рендер и доступ к ресурсам в инструментах поисковиков. Рассмотреть серверную/статическую генерацию основного содержимого новостей с собственными материалами, а не полагаться только на JS.

### 6. Нерабочий RSS — P1

`rss.xml:315` не проходит XML-парсинг из-за неэкранированного `&` в ссылке. `scripts/generate_rss.py` формирует XML строками и не экранирует ссылки; вставка внешнего текста в CDATA также требует обработки `]]>`. Это может ломать подписку читателей и агрегаторов.

**Действия:** генерировать RSS через XML-библиотеку, валидировать feed в CI и проверять, что содержимое и ссылки соответствуют выбранной модели публикации.

### 7. Метаданные и сниппеты — P2

- `scripts/update_metadata.py` каждые полчаса формирует title и description из случайных слов первых новостей. Текущий `trends.html` содержит несвязный список слов и английский месяц; это снижает понятность сниппета. Использовать стабильный человеческий title/description без набивки ключевыми словами.
- `images/og-cover.jpg`, указанный как OG-изображение на главной и нескольких внутренних страницах, отсутствует в репозитории; превью при публикации ссылки может быть без картинки. `1favicon.ico`, указанный на девяти страницах, также отсутствует. Создать реальные файлы или заменить ссылки, проверить публичные HTTP-ответы.
- `projects.html`, `tools.html`, `wiki.html`, `trends-logistics.html` не имеют meta description; это не препятствует индексации, но ограничивает контроль над сниппетом. Микроразметка JSON-LD найдена только в `trends.html`; рассмотреть Person/ProfilePage/BreadcrumbList там, где соответствует видимому контенту, без ожидания гарантированных расширенных результатов.
- Многие страницы намеренно содержат `noindex`, включая `library.html` и `scm-platform/calculators.html`. Уточнить, какие материалы должны привлекать поисковый трафик, и только после этого менять директивы.

## Функциональность и пользовательский опыт

### 8. Мобильная навигация на основных страницах — P1

`index.html:42` и `about.html:42` скрывают `nav ul` при ширине до 900 px; в соответствующей шапке альтернативная кнопка меню не найдена. Такая же конструкция используется и на других страницах портфолио. На `trends.html` реализовано отдельное мобильное меню. В результате основные разделы могут быть недоступны из шапки на мобильных устройствах, хотя другие ссылки на странице могут оставаться.

**Действия:** добавить доступное мобильное меню с кнопкой, состоянием `aria-expanded`, управлением клавиатурой и закрытием по Escape; протестировать 320–900 px и различные масштабы.

### 9. Неработающие внутренние ссылки — P1/P2

Локальная проверка обнаружила:
- `wiki.html`: 26 ссылок на отсутствующие файлы в каталоге `wiki/`.
- `certificates.html`: отсутствуют `files/diplom-mba-logistika.pdf`, `diplom-operator-logist.pdf`, `diplom-ats-control.pdf`, `1c-bitrix-certificate.pdf`.
- `auditor.html`, `checklist.html`, `inventory-methodology.html`, `kpi-center.html`, `library.html`: ссылки на отсутствующий корневой `dashboard.html`; в `checklist.html` также отсутствует корневой `checklists.html`.
- `scm-platform/meetings-list.html` ссылается на `meeting-protocol.html`, тогда как в репозитории файл называется `meeting-protocol.htm`.

Проверка определяет наличие файлов, а не фактический HTTP-статус или предназначение ссылок. Исправить адреса, добавить согласованные материалы либо явно отключить недоступные действия; включить проверку внутренних ссылок в CI.

### 10. PWA / service worker — P2

`manifest.json` задаёт `start_url: /Panibratsky-Dmitry/`, а `CNAME` указывает на корневой домен `scm-news.ru`. `sw.js:3–20` кэширует тот же префикс и отсутствующий `1favicon.ico`; `cache.addAll` в `sw.js:23–26` отклоняет установку при неуспешной загрузке любого обязательного ресурса. На custom domain пути, вероятно, неверны; реальные HTTP-ответы не проверялись. При успешной установке фиксированная версия кэша и cache-first для большинства запросов могут оставлять устаревший контент.

**Действия:** согласовать базовый путь с реальным развёртыванием, проверить все precache-ресурсы, стратегию обновления и удаление старых кэшей; отдельно проверить установку, запуск и работу офлайн в браузере на боевом домене.

### 11. Подписка может сообщать об успехе без доставки — P2, требуется проверка интеграции

`js/subscribe.js:18–48` сначала сохраняет email в localStorage посетителя, а затем отправляет запрос только при наличии глобального `BACKEND_URL`. Ошибки сети не препятствуют сообщению об успехе; `no-cors` также не позволяет убедиться в успешной обработке сервером. Скрипт подключён в `trends.html`, но наличие работающей формы и конфигурации необходимо проверить по реальному пользовательскому сценарию.

**Действия:** реализовать проверяемый ответ backend, отображать успех только после подтверждения, обрабатывать ошибки и обеспечить корректное согласие/отписку в соответствии с применимым законодательством.

### 12. Производительность, качество данных и доступность — P2

- `prompts.html` весит 4 600 139 байт (~4,39 МиБ) без учёта сжатия; возможны высокая стоимость первоначальной загрузки и обработки DOM. Измерить Lighthouse и реальные CWV, затем рассмотреть разбиение, пагинацию или отложенную загрузку.
- `data/news.json` содержит 889 записей и 806 уникальных значений ссылки; повторяющиеся ссылки могут создавать дубли в ленте. Уточнить правила нормализации и дедупликации.
- На ряде страниц несколько `<h1>`, а у полей входа в `login.html` используются placeholder вместо видимых `<label>`. Проверить семантику, доступные имена, контраст, фокус и работу без мыши; автоматическая проверка не заменяет ручную.
- Google Analytics и Яндекс.Метрика подключаются на публичных страницах, а на `trends.html` включён Webvisor. Проверить информационное уведомление, основания обработки, политику конфиденциальности и настройки согласия применительно к юрисдикциям аудитории с профильным специалистом. Юридического вывода по одному коду сделать нельзя.

## Дополнительный риск внедрения кода — P1, требует проверки

В `trends.html:999–1013, 1214–1216` внешние поля новости подставляются в HTML и атрибуты, однако `escapeHtml` экранирует только `&`, `<`, `>`, но не кавычки; URL не проверяется на допустимую схему. В `cabinet.html:448, 493–497, 909` есть аналогичные контексты. При попадании специально сформированных данных во входной поток возможно внедрение разметки/скрипта; фактическая эксплуатация и возможность управления данными не проверялись.

**Действия:** для текста использовать `textContent`, для атрибутов — DOM API, валидировать URL и разрешать только `http:`/`https:`; для HTML при необходимости применять проверенную санитизацию. Добавить тесты с кавычками и опасными схемами. Проверить правила доступа и происхождение данных. Версионировать сторонние библиотеки и оценить SRI/CSP как дополнительные меры; отдельно проверить применимость к динамическим скриптам аналитики.
