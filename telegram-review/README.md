# Сервер очереди на согласование: локальный прототип

Статус: **не развёрнут и не подключён к каналу**. Отдельный Cloudflare Worker с D1 принимает подготовленный текст и ссылку по закрытому `/intake`, отправляет текст на проверку в личный чат редактора; только кнопка владельца из того же сообщения может запустить отправку в канал. Автоматический отбор новостей, графический редактор текста, карточки-картинки и интерфейс восстановления не реализованы. Ручная подготовка отдельного черновика из `news.json` описана ниже. HTML-макет `tools/telegram-draft-preview.js` — не изображение Telegram. Никакой генерации AI нет; содержимое, права и источник проверяет человек. Без источника создать черновик нельзя.

## Защита и границы

* `REVIEWER_ID` — числовой **личный** Telegram user ID, используемый и как ID приватного чата; перед отправкой в этот чат пользователь должен открыть бота и нажать Start. ID канала — `CHANNEL_ID`. Эти значения хранятся как секреты, не в Git.
* Bot API token, секрет webhook и секрет приёма хранятся только в секретах Worker. Webhook проверяет Telegram `X-Telegram-Bot-Api-Secret-Token`, user ID, тип чата, ID чата и ID сообщения. Два разных случайных секрета длиной не менее 32 символов (`A-Z`, `a-z`, `0-9`, `_`, `-`). Не вставляйте в конфигурацию, Git, скриншоты, лог, URL или чат.
* `/intake` принимает только POST JSON с заголовком Authorization Bearer и полями `text` и `source_url`; этот секрет выдаётся только доверенному отправителю. Рекомендуется отдельный бот: существующая интеграция Telegram → Сетка не меняется. Переустановка webhook для существующего бота может отключить его прежнюю обработку обновлений; не делайте этого без проверки.
* D1 уникально ограничивает URL. Повторный клик обрабатывается атомарным переходом из `ready`. Все сообщения — простой текст, а не HTML. Дубликаты с разными URL возможны; источники и факты нужно проверять вручную.
* `notifying` и `sending` — неопределённые состояния: ответ Telegram мог потеряться после успешной отправки. Бот **не повторяет отправку** и не пытается сам решить, что произошло. Сначала вручную проверьте личный чат или канал и базу. Не переинициализируйте и не сбрасывайте журнал: процедура безопасного восстановления ещё не реализована. Если удалось отправить в канал, а запись в БД не удалась, запись остаётся `sending`.
* Доступность облака, квоты, задержки, резервные копии, защита аккаунта, права бота и фактическая доставка не проверены. Гарантия exactly-once невозможна. Не включать текущий автоматический workflow, пока новый процесс не пройдёт проверку.

## Локальные тесты

Из корня: `node --test tests/telegram-review.test.mjs` и `node --check telegram-review/worker.mjs`. Тесты используют подставные базу и Telegram API; это не интеграционные тесты D1 или Telegram.

## Что потребуется для развёртывания (не выполнялось)

1. Бесплатный аккаунт Cloudflare, проверка действующих ограничений и доступности регистрации; без перехода на платный тариф. Создать D1-базу и применить `schema.sql`. Сделать резервную копию перед любыми операциями с состоянием.
2. Локально скопировать `wrangler.toml.example` в игнорируемый `wrangler.toml`, указать ID базы; создать секреты Worker `BOT_TOKEN`, `WEBHOOK_SECRET`, `INTAKE_SECRET`, `REVIEWER_ID`, `CHANNEL_ID` через защищённый механизм поставщика. Не хранить их в Git и не отправлять в переписку.
3. Создать и настроить отдельного Telegram-бота, открыть с ним личный чат, предоставить необходимые права в **тестовом** канале. Развернуть Worker, зарегистрировать webhook с секретом и провести проверку в тестовом канале, а не в основном. Не печатать URL Bot API с токеном в логи.
4. Сначала проверить передачу черновиков с настоящими Telegram и D1, реализовать визуальные изображения, наблюдение за ошибками и процедуру сверки неопределённых состояний; затем проверить границы доступа, безопасность и кнопки. Проверить, что в канал не попадает ничего до нажатия. Только после этого отдельно решать о подключении основного канала.

Бесплатные лимиты и условия проверяются на день подключения: https://developers.cloudflare.com/workers/platform/limits/ и https://developers.cloudflare.com/d1/platform/pricing/ . При исчерпании бесплатных лимитов система может остановиться; платный тариф не подключать без отдельного согласия.

## Подготовка и отправка одного черновика

Эти команды вручную готовят **один** черновик и после отдельного подтверждения передают его в очередь; автоматически не запускаются и не включают старую рассылку. Сначала нужен настроенный Worker, отдельный тестовый канал и проверенные секреты. До этого можно выполнить только первые шаги, не обращаясь к сети.

1. `node telegram-review/drafts.mjs list` показывает индексы текущего `data/news.json`. Список не учитывает журнал отправок: новость может уже быть опубликована. Поскольку файл обновляется, перед созданием убедитесь, что индекс указывает на нужную запись.
2. Создайте игнорируемую папку `private-drafts` и выполните `node telegram-review/drafts.mjs prepare 0 private-drafts/draft.json` (замените 0 нужным индексом). Файл создаётся только если его ещё нет. Это локальный черновик — он не меняет ленту и никуда не отправляется.
3. Откройте JSON, проверьте первоисточник и права, исправьте заголовок и описание, заполните `comment` своим выводом. Только после проверки установите `ready_for_review` в `true`. Это согласие **отправить на проверку в личный Telegram**, а не разрешение публикации в канал. Текст не фактчекинг и не AI-резюме.
4. После настройки тестового Worker задайте в защищённом окружении `REVIEW_INTAKE_URL` (HTTPS-адрес Worker на `workers.dev`, путь `/intake`) и `REVIEW_INTAKE_SECRET`. Не добавляйте значения в команды истории оболочки, скрипты, Git или переписку. Затем `node telegram-review/drafts.mjs submit private-drafts/draft.json` отправит **один** запрос. Worker направит черновик на личное согласование. При таймауте или ошибке сначала проверьте чат и журнал: повтор может привести к дублированию; автоматических повторов нет.

Изображения пока не передаются. Старая рассылка по расписанию должна оставаться выключенной. Локальные черновики в `private-drafts/` игнорируются Git, но не защищены от других пользователей устройства; не храните в них конфиденциальные данные. Проверки: `node --test tests/telegram-review-drafts.test.mjs`.

## Локальные PNG-карточки

`card.py` создаёт квадратную карточку 1080 × 1080 из заголовка и названия источника в подготовленном JSON. Она не читает сеть и не использует платный AI-сервис. Установите бесплатную зависимость в своё виртуальное окружение: `python -m pip install -r telegram-review/requirements-visuals.txt`. По умолчанию используются локальные шрифты DejaVu Sans из `/usr/share/fonts/truetype/dejavu/`; при отсутствии задайте пути к установленным кириллическим TTF-файлам флагами `--font-regular` и `--font-bold`.

Пример: `python telegram-review/card.py private-drafts/draft.json private-drafts/card.png`. Существующий PNG не перезаписывается. Длинный заголовок может обрезаться с многоточием — обязательно откройте карточку и проверьте читаемость и смысл. Источник, факты и права нужно проверить вручную; программа этого не делает.

**Ограничение:** полученный PNG пока не передаётся в Worker или Telegram. Это локальная заготовка для следующего этапа, не работающая публикация с изображением. Примеры и черновики в `private-drafts/` не включаются в Git и Pages.
