# Исправления по аудиту

## Сделано в репозитории

- Удалены заранее заполненные учётные данные из формы входа. Важное ограничение: это не отзывает пароль и не удаляет его из истории Git.
- Убрано представление клиентского пароля как защиты кабинетов: они помечены локальными инструментами без защиты доступа, с предупреждением о конфиденциальных данных. Автозагрузка заявок в локальный кабинет отключена. Firebase и Apps Script по-прежнему требуют независимой серверной проверки и настройки прав; публичный HTML не может обеспечить их защиту.
- Исправлены генераторы sitemap и RSS, созданы корректные XML-файлы. В sitemap только собственные индексируемые страницы; RSS исключает повторяющиеся ссылки и XML экранируется. Убран автоматический набор случайных ключевых слов в метаданных.
- Настроены canonical для самостоятельных публичных страниц, добавлены описания для ряда страниц, разрешено сканирование ресурсов в robots.txt. Служебные страницы помечены `noindex`; это не защита от доступа.
- Исправлены ссылки на существующие разделы, отсутствующие PDF и статьи отмечены как недоступные вместо ссылок на несуществующие файлы. Заменены отсутствующие favicon и OG-изображение на имеющиеся иконки.
- Добавлено мобильное меню с управлением клавиатурой и aria-атрибутами; до загрузки JS ссылки остаются видимыми. Улучшено мобильное меню новостной страницы.
- Исправлены пути PWA, сервис-воркер использует сеть прежде всего и не кэширует данные кабинета. Новостная лента отбрасывает некорректные URL и повторы, экранирует динамические атрибуты. Экранирование усилено в локальных кабинетах.
- Отправка подписки без подтверждённого сервера больше не сообщает ложный успех. В текущих HTML форма с идентификатором, который ожидает скрипт, не обнаружена; для запуска подписки нужна рабочая интеграция.
- Исправлена потеря существующих новостей при обновлении: лента объединяется с новыми материалами, дедуплицируется, сортируется по реальным датам, записывается атомарно и сохраняется при сбоях источников. Публикуется HTML-снимок ленты для работы без JS; адреса и текст экранируются.
- Проверка ссылок больше не помечает тайм-ауты, 403 и 5xx как мёртвые, повторно проверяет ранее отключённые ссылки. Расписания записи данных объединены в группу последовательного выполнения.
- В калькуляторах устранены ошибки проверки нулевых и отрицательных значений; запас рассчитывается как явно обозначенная оценка без обещания уровня обслуживания, стоимость перевозки — по тарифу за километр без произвольного коэффициента веса.
- Убрана подстановка секретов почты в исходный код Python и вывод фрагментов писем в журнал. Экранированы сообщения чат-ботов и значения в окне промпта.
- Добавлено сохранение состояния отправок Telegram между запусками через кэш GitHub Actions. Кэш может быть вытеснен: для гарантированной защиты от повторной отправки необходимо долговременное хранилище.
- Добавлены автоматические проверки XML, canonical, файлов, генерации снимка, объединения новостей, сценариев калькуляторов и отсутствия предзаполненного пароля; проверки XML и страниц запускаются и после генерации новостей в workflow.

## Обязательные действия вне репозитория

1. Срочно сменить опубликованный ранее пароль Firebase и везде, где он повторялся; отозвать сессии и проверить журналы доступа. Считайте пароль скомпрометированным даже после исправления HTML.
2. Проверить и ограничить доступы Firebase/Storage/Firestore и Google Apps Script, особенно чтение и изменение подписчиков и заявок; применять авторизацию на сервере. Снятие пароля в интерфейсе не делает открытый backend безопасным. Не хранить чувствительные данные в статических файлах или localStorage на общих устройствах.
3. Развернуть изменения, проверить HTTP-ответы, редиректы, security headers, работу PWA и меню на реальных устройствах. Проверить заголовки и правила хостинга, в том числе CSP, с учётом сторонних скриптов.
4. После публикации отправить sitemap в Google Search Console и Яндекс Вебмастер, проверить URL Inspection, фактическую индексацию, выбранные canonical и динамику показов/кликов. По исходникам невозможно подтвердить позиции или попадание в индекс.
5. Подготовить настоящую OG-обложку, опубликовать недостающие статьи и документы либо убрать соответствующие карточки. Оценить производительность крупной страницы `prompts.html` по Lighthouse и реальным Core Web Vitals.
6. Проверить на соответствие применимому законодательству политику конфиденциальности, аналитические счётчики и согласие на обработку персональных данных; согласовать и настроить работающий подписной backend.
7. Провести отдельный комплексный пентест, браузерное тестирование основных сценариев и accessibility-аудит. Исправления выявленных участков не доказывают отсутствие всех уязвимостей и ошибок.
