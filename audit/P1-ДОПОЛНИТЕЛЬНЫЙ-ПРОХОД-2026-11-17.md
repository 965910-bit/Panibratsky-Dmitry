## Что добавлено в репозитории

- Локальные Font Awesome 6.4.0 и Leaflet для legacy HTML; сверка с npm, пути и лицензия. На пяти страницах локальный Chromium с блокировкой внешней сети загрузил стили/шрифты и нашёл glyphs на 412 и 1366 px; не полная визуальная проверка.
- Для основных Python workflow добавлены lockfiles с SHA-256 и установкой `--require-hashes`; Pillow обновлён с 11.3.0 до 13.0.0. Доступность всех зафиксированных distributions для Python 3.10 Linux и генерация карточек с Pillow 13 локально проверены; запуск изменённых GitHub workflow ещё не проверен. Lock не защищает от компрометации до фиксации и не фиксирует бинарник Chromium, скачиваемый Playwright, или GitHub Actions по полному SHA.
- `pip-audit` (PyPI, 17.11.2026) для `links.lock`, `hh.lock` и Pillow не сообщил известных уязвимостей; для `news.lock` сообщил CVE-2026-126190/126193/126191 в `soupsieve==2.10`, с рекомендациями 4.0.0/3.0.2, которые на доступном PyPI на момент проверки не найдены. Эти сообщения требуют перепроверки и обновления при появлении исправления; наличие lock не устраняет их. Источники новостей не включались. До исправления избегать недоверенных CSS-селекторов; текущий код содержит статический селектор в приостановленном ATI collector. Это не доказательство отсутствия других путей эксплуатации.
- Подготовлен IndexNow: публичный ключ, фильтр изменённых canonical HTML из sitemap, проверка актуальности main, успешного Pages, предыдущего деплоя, опубликованного ключа, sitemap, байтов, canonical и noindex; никакого реального POST не было. Unit-тесты моделируют ответы, а не публичный деплой. `workflow_run` от управляемого legacy `pages-build-deployment` не доказан; проверить после публикации. При повторном деплое одного SHA изменений нет. Из-за отсутствия журнала успешных отправок пропущенный устаревший деплой и быстрые последовательные публикации могут оставить изменения без уведомления; проверка main повторяется перед POST, но атомарности нет. Удаления, зависимые изменения только CSS/JS и изменения вне sitemap не отправляются; 200/202 — не подтверждение индексации. Публичный ключ не пароль.
- GitHub API показал успешный `check_broken_links.yml` run `44099561491`; в двух неудачных HH runs `44075755557` и `43852732852` упали соответственно шаг сбора и шаг push, причины не установлены. Прежний отдельный диагностический HH run получил 403; не обходить ограничения. Новые версии зависимостей пока не проверены запуском Actions.
