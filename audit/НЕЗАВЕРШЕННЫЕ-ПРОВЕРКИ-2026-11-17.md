## HTTP и безопасность: важное обнаружение

В том же Actions run read-only probe без перехода по редиректам получил для фиксированных URL:

| Адрес | Результат |
|---|---|
| `http://scm-news.ru/` | HTTP 200, не редирект на HTTPS, HSTS отсутствует |
| `https://scm-news.ru/` | HTTP 200, HSTS, CSP и CSP Report-Only, X-Frame-Options и X-Content-Type-Options в ответе не обнаружены |
| `http://www.scm-news.ru/` | 301 на **HTTP** apex |
| `https://www.scm-news.ru/` | ошибка TLS, конкретная причина не установлена |
| случайный отсутствующий HTML | HTTP 404 |
| `/index.html` | HTTP 200; canonical проверяется существующим SEO guard, доступ по alias не подтверждает индекс |

Это не полная инвентаризация субдоменов, сертификатов, цепочек редиректов, безопасности или тестирование из разных сетей. GitHub Pages API показывал `https_enforced=false`. **HTTP-вариант реально доступен без шифрования**; не вводить через него конфиденциальные данные. Нужен разбор поддержки `www` и сертификатов, поэтапное включение HTTPS redirect на управляемом хостинге/edge и проверка прямых ссылок и отката. Настройки Pages/доступа в этом проходе не менялись. HSTS `includeSubDomains` и preload без полной инвентаризации и решения владельца опасны; CSP/Trusted Types и WAF требуют управляемого edge, staging, наблюдения и теста работающих сервисов. Не выдавать статические файлы за эти механизмы.
