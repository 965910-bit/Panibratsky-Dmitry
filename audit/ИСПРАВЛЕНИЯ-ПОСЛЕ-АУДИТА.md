# Исправления после аудита

Изменения подготовлены в PR, до слияния и развёртывания на работающем сайте их нет.

- География публичного позиционирования и facts сервера: Сургут и ХМАО в приоритете, частые командировки, переезд при предоставлении релокационного пакета. Резюме не менялись.
- На пяти старых страницах обе фотографии в скрытой современной темой шапке переведены на lazy loading и адаптивные WebP, сохранены исходные JPEG как запасной вариант. WebP созданы из тех же оригиналов без изменения кадра. В локальном Chromium, при блокировке внешних ресурсов, до изменения запрашивались оба JPEG на каждой странице при ширине 375 и 1200 px; после — ни один. Для видимой версии старой шапки предусмотрены варианты шириной 320/480/640 px. Это не замер реальных Core Web Vitals или сетевой скорости; фактическое поведение зависит от браузера.
- Лента загружается по постоянному адресу с `cache: no-cache`: браузер должен перепроверять актуальность, а не всегда скачивать файл с новым URL. Локальный тест на сервере с ETag проверяет 200 → 304 → 200 при изменении данных. Ответ реального хостинга и эффект после публикации не проверены.
- Пустой файл `data/manual_news.json` приведён к корректному JSON-массиву. Текущие данные пользователей в localStorage не менялись. Уточнены сообщения кабинета: в нём нет автоматического получения подписчиков/заявок и подключения экспортированного JSON к ленте.
- `js/analytics.js` содержит HTML старой локальной аналитики, а не JavaScript-модуль; репозиторные сценарии на него не ссылаются, но тесты намеренно проверяют его содержимое. Переименовывать или удалять без проверки внешних ссылок и плана совместимости рискованно. Существующая публичная страница рынка — отдельный `analytics.html`.

## Осталось за пределами этого PR

Настоящая защита требует доступа к серверной инфраструктуре: публичный GitHub Pages и клиентский localStorage не обеспечивают авторизацию. Не хранить секреты и персональные данные в публичном репозитории или локальных инструментах; публичность уже опубликованной истории Git отдельным исправлением страницы не отменяется. Правила Firebase, production Worker/D1 и внешний хостинг AI-сервера нужно отдельно проверить в соответствующих кабинетах. Ранее раскрытый пароль следует сменить и отозвать сессии, если это ещё не сделано. Отдельно после публикации проверить реальную доставку аналитики и настройки целей, индексацию и показатели производительности. Файл каталога промптов намеренно оставлен без разбиения: он уже загружается отложенно; изменение формата требует отдельной проверки совместимости.
