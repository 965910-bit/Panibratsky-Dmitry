## Существующий ETL и воспроизводимость

`scripts/open_logistics_data.py` получает и проверяет обе фиксированные API-выборки, сохраняет `data/open-logistics.json` только после успеха обоих источников; при сбое старый файл не заменяется. На момент первоначального описания в Git сохранялись версии нормализованного снимка, но исходные ответы API, полная история и версия методологии источника автоматически не архивировались; новое архивирование описано в дополнении ниже. Поэтому воспроизводимо проверить сохранённое преобразование в рамках известных входов можно лишь при наличии исходных ответов; прошлый внешний API-ответ по одной контрольной сумме восстановить нельзя.

Новая команда без сети и записи:

```sh
python3 scripts/open_data_review.py data/open-logistics.json --require-complete
python3 scripts/open_data_review.py data/open-logistics.json --previous /path/to/older-snapshot.json --require-complete --reject-regression
```

JSON-отчёт содержит SHA-256 входных файлов, значения, источник, единицы и один из статусов: нет прошлого снимка, пропущенное наблюдение, прежний период, новый период, изменение значения/статуса за тот же период, неизменившееся наблюдение. `--require-complete` отклоняет отсутствие текущего значения; `--reject-regression` даёт ненулевой код при откате периода. Изменение за тот же период — сигнал для проверки, а не доказанный пересмотр источником. При новом периоде старое значение исходным API может быть недоступно: сравнение **не проверяет** пересмотр исторического ряда и пропуски между годами; никаких выводов о росте или квартальной динамике не делает. Время `saved_on` — дата записи, не время получения или наблюдения.

Workflow открытых данных на `main` теперь сравнивает новый сохранённый снимок с временной копией прошлого перед commit: при отсутствии текущего значения или откате периода публикация прерывается; изменение того же периода фиксируется в логе, но **не требует ручного утверждения**. На других ветках по-прежнему только существующий сетевой `--check`. В CI новая команда проверяет сохранённый снимок без сети. Новое расписание/commit workflow на GitHub и сеть внешних API в этой ветке ещё не проверены.

## Условия возможного будущего выпуска

Согласовать тему и отдельные ряды, проверить права и методологию каждого, определить периоды, частоты, географию, единицы, качества, критерий достаточности данных и редактора. Сохранять разрешённые исходные ответы/версии, даты получения, хэши, код и параметры, журнал исправлений, а также явно помечать отсутствующие/предварительные значения. После независимой сверки публикации размещать машиночитаемые данные с атрибуцией и границами применимости. Эти два несопоставимых годовых среза не дают оснований для квартального обзора или самостоятельного «официального индекса».

## Дополнение: архивирование исходных ответов

В следующем изменении добавлено архивирование точных байтов **только уже используемых** двух API при будущих обновлениях на `main`. Каждая уникальная пара ответов хранится в `data/open-logistics-archives/<хеш>/` вместе с манифестом: ссылки источников и условий, UTC-время записи, хеши, версия преобразования и нормализованные наблюдения. Совпадающие байты повторно не сохраняются; разные ответы, в том числе изменившиеся метаданные, создают новые версии и могут со временем увеличивать Git. Автоматической политики удаления истории нет. Архив публичен в Git и Pages; нельзя сохранять в него приватные данные. Перепроверять условия и исключения источников при изменении наборов.

`python3 scripts/verify_open_archive.py data/open-logistics-archives/<хеш>` без сети и записи сверяет хеши и повторно вычисляет показатели из байтов. Это контроль целостности и воспроизводимость преобразования, не доказательство аутентичности первоисточника. До запуска новой версии архивов нет: прежний снимок, просмотренный через веб-инструмент, не обладает восстановимыми исходными байтами. Полученные здесь ответы двух API повторно показали в веб-инструменте значения, совпадающие с сохранённым снимком (World Bank 2022 и Eurostat 2025); это не тест runner и не наблюдение квартальной динамики. Конкретные новые данные, например Росстат, не подключены.

Новый вариант workflow и его запись ещё не выполнялись в реальном GitHub runner. На тестовых фикстурах проверены сохранение точных байтов, повторная обработка, дедупликация, повреждение и отказ при отсутствии входов. Как и прежде, сравнение только последних наблюдений не выявляет все пересмотры исторического ряда. После изменений API или алгоритма может потребоваться новая версия преобразования и отдельная миграция архива.

## Фактический архив и различие методологий — 17 ноября 2026

GitHub Actions run 44180012449 получил оба API, проверил результаты и сохранил первый архив в текущую рабочую ветку. В нём ответы зафиксированы в 21:27:38 UTC, вместе с манифестом и хешами; `verify_open_archive.py` проверен повторно локально. Это не архив ответа, из которого получен прежний снимок. Автоматический commit на `main` и выполнение расписания пока не проверены. Ручная диагностика без опции сохранения создаёт только временный артефакт; опция `persist_diagnostic=true` записывает проверенные публичные ответы в вызванную ветку (не в `main`) и требует права записи.

В архивном ответе World Bank есть семь ненулевых исторических наблюдений 2007–2022, а ответ Eurostat ограничен последним годом. `scripts/open_history_review.py` сравнивает все ненулевые наблюдения World Bank с ближайшим предыдущим проверенным архивом и отмечает добавленные, исчезнувшие и изменённые значения. Workflow выводит результат в лог; изменения не блокируют автоматический commit и требуют интерпретации. Один архив не позволяет определить пересмотры; нулевые значения API не означают ноль, годы без опроса не называются пропусками. Версии методологии и полная история Eurostat в этом потоке не архивируются.

По [метаданным World Bank](https://databank.worldbank.org/metadataglossary/world-development-indicators/series/LP.LPI.OVRL.XQ), наблюдение WDI за 2022 относится к опросу для выпуска LPI 2023. [LPI 2.0](https://lpi.worldbank.org/en/home) перестроен на данные отслеживания перевозок и охватывает иные показатели: он не является прямым продолжением старого опросного балла. Период 2022 в старом ряду не означает значение нового LPI 2.0 и не отражает текущую ситуацию в реальном времени.
