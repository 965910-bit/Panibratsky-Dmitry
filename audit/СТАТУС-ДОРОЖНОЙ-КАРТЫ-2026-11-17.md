# Дорожная карта: сверка и следующие шаги

Сверка 17 ноября 2026 по исходной дорожной карте `ROADMAP-SEO-SECURITY-GEO-2026-11-17.md`, репозиторию и объединённым PR #59–69. Исходная карта — исторический снимок, не автоматически обновляемый отчёт; объединение PR не подтверждает работу продакшена. Это не полный повторный аудит, не замена полевым замерам и не проверка кабинетов. Каталог `audit` публичен в Git и исключён из Pages; секреты и персональные данные сюда не вносить.

## Что уже сделано частично

- Фактчекинг: в PR #69 исправлен OTIF и ограничены отдельные неподтверждённые показатели; эта работа не подтверждает все остальные цифры. В текущем изменении отключено автоматическое создание задач по непроверенным порогам в KPI-центре; подробности и оставшиеся риски — `FACTCHECK-OTIF-2026-11-17.md`.
- Источники: составлен реестр условий и реализованы отдельные показатели World Bank и Eurostat, но не запущен новый поток новостей. `SOURCES = []`, государственный сборщик приостановлен; страница предупреждает о возможной неактуальности. Дата последнего успешного сбора не подтверждена.
- SEO и безопасность: усилены локальные проверки sitemap и ссылок, исправлены некоторые DOM XSS и сведена часть Chart.js к локальной версии. Проверка доменов ссылок ещё не проводится: `APPROVED_HOSTS` пуст. CSP/Trusted Types, управляемые серверные заголовки, антискрапинг и фактический доступ проверенных ботов остаются непроверенными.
- Аналитика: минимизированы ручные события на странице новостей; настройки согласия, автоматические события, приём данных и кабинеты не проверены.

## Что осталось, в рабочем порядке

1. **P0 — фактчекинг:** продолжить по `factcheck-todo.md`, включая оставшиеся отраслевые цифры, архивные прогнозы и оценки. Утверждения о личных достижениях требуют подтверждения владельцем/документами. Не подменять отсутствие источника предположениями. Для KPI отдельно исследовать пользовательские цели, старые истории, отчёты и расчёты, прежде чем возвращать автоматические задачи.
2. **P0 — новости:** самостоятельно продолжать исследовать источники, лицензию и доступность; не подключать автоматическую публикацию без подтверждения прав и безопасного транспорта. Сохранить разделение мониторинга, оригинального комментария и проверки редактором. Не принимать пустой список источников за успешный сбор и не подставлять дату обновления файла вместо даты успешного сбора.
3. **P0 — индекс, CWV, аналитика:** собрать реальные baseline p75 по устройствам и периодам и лабораторные трассы, проверить Search Console/Вебмастер и GA4/Метрику при наличии доступа. При отсутствии данных отмечать «не измерено»; не считать цели CWV достигнутыми. Проверить noindex/robots по каждому публичному URL, помня, что robots не защищает приватные данные.
4. **P0/P1 — защита:** измерить реальные HTTP-ответы/редиректы, установить контролируемую инфраструктуру, затем тестировать заголовки и CSP в безопасном режиме; HSTS preload, Trusted Types и антибот — только после совместимости, проверки и плана отката. Сохранить доступ поисковых и AI-ботов. По явному решению владельца существующие доступы Firebase/Apps Script и ранее раскрытый пароль в этой работе не меняются.
5. **P1 — зависимости и SEO/GEO:** проверить остающиеся CDN и обновления Dependabot вместе с тестами; продвигать Answer-First только на проверенном содержимом, проверить canonical, индексирование, структурированные данные и IndexNow после определения успешного деплоя. Исследовать конкурентов и релевантные ссылки без выдуманных результатов.
6. **P2 — Data Hub и рост:** выбирать конкретные лицензированные наборы, сохранять методологию и обновления; не называть отдельный показатель новым официальным индексом. Международные версии и коммерческие страницы — при подтверждённом спросе и реальном предложении.

## Ограничения конкретного изменения

Локальные тесты с имитацией DOM проверяют повторный рендер, сохранение, импорт, старую историю, дробные значения и отсутствие новых задач. Не проверялись реальные браузеры, печать, консоли аналитики, production deployment и реальные данные пользователей. На дашборде остаются демонстрационные пороги и экстраполяция без интервалов времени; они маркированы, но не валидированы. По вопросам о реальных показателях, доступах и целях не следует выдавать неподтверждённые предположения за факты.

## Дополнение: Google Alerts и риск публикации

На момент проверки `Update News` запускал сбор Google Alerts и затем `git add data/`; отдельный `data/google_alerts.json` отслеживается Git и содержит ранее собранные метаданные писем. В этой работе не исследовались конкретные сообщения и не утверждается наличие в них персональных данных; опасность — возможность будущей публикации тем и ссылок из почты, а не доказанная утечка конкретного письма.

Новые кандидаты теперь сохраняются только во временный `.local-news/google_alerts.json` (исключён из Git и Jekyll, файл с ограниченными правами), шаг использует явный список публикуемых файлов, а основной сборщик больше не импортирует Alerts даже при добавлении источника. IMAP открывается read-only, письма читаются через PEEK, содержимое и ошибки почты не печатаются намеренно. Существующий публичный `data/google_alerts.json`, история Git и кэши не удалены, права доступа и учётные данные не изменены. Сбор в GitHub Actions не сохраняет результат после завершения runner, долговременное приватное хранилище и редакционный процесс необходимо спроектировать отдельно. Из-за `continue-on-error` общий успех workflow не подтверждает успешное получение писем; локальный файл также нельзя считать подтверждённым источником или разрешением на публикацию. Почта, реальный runner и публичный сайт в этом изменении не проверялись.

## Дополнение: аудит и чек-листы — защитная приостановка

Встроенные и пользовательские пороги больше не используются для автоматических оценок и задач в двух соответствующих формах; новые аудиты сохраняют ручные ответы и факты без оценки. Старые оценки и задачи сохранены, их нельзя считать подтверждёнными; ранее статус «Нет» устанавливался по умолчанию. История, взаимодействие с реестром и отчётами, отдельная приостановка печати категории и ограничения описаны в `AUDIT-CHECKLIST-SAFETY-2026-11-17.md`. Нужна отдельная методология и проверка требований; реальный браузер и печать не проверены.

При дальнейшей проверке PR добавлена защита хранилища расширенной формы от удаления через старый реестр, включение скрытых ответов в экспорт и подтверждение импорта/загрузки. Многоключевой импорт не является атомарным, полная валидация JSON и проверка браузера остаются открытыми; подробности — `AUDIT-CHECKLIST-SAFETY-2026-11-17.md`.
